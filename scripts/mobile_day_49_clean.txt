Concept Invariant &amp; Guardrail Standard HTTPS can be intercepted on mobile devices using proxy tools (Charles, Proxyman, Burp Suite) if the user installs a rogue root certificate. SSL Pinning guarantees communication only with the bank's exact public key. Failure Mode: Deploying release APKs/AABs without ProGuard/R8 obfuscation, allowing attackers to decompile the app into readable Java/Kotlin source code via jadx. TryIt Friction Challenge: Configure SSL pinning in React Native using react-native-ssl-pinning with SHA-256 public key hashes, rejecting MITM proxy connections. 3-Tier Socratic Hint Ladder: 1. Nudge: Why is standard HTTPS not enough to prevent MITM attacks on a rooted mobile device? 2. Visual Memory: An attacker with root access can install a custom CA certificate into the phone's system trust store, allowing tools like Charles Proxy to decrypt all HTTPS traffic in plaintext! 3. Surgical Line Fix: Enforce SSL Pinning so the app only trusts your specific server's public key hash. Situational Production Puzzle (FAANG / Staff Screen): Scenario: A penetration tester intercepts all banking API traffic from an iPhone using Charles Proxy. The app continues working without warnings. What security control must be implemented immediately? Correct Answer: Option 2 &mdash; Implement SSL Public Key Pinning (HPKP), causing the app's networking layer to immediately abort TLS handshakes if the server certificate does not match pinned hashes. Debrief: SSL Pinning pins the server's public key inside the mobile binary. Any proxy attempting to inspect traffic presents a different certificate, triggering an instant TLS abort.
