Concept Invariant &amp; Guardrail Never store access tokens, refresh tokens, or cryptographic keys in standard AsyncStorage or MMKV without hardware encryption. Hardware keychains protect keys even if the OS filesystem is dumped. Failure Mode: Storing sensitive JWT bearer tokens in plain unencrypted AsyncStorage, allowing rooted or jailbroken devices to extract tokens via adb or file explorers. TryIt Friction Challenge: Store and retrieve JWT session tokens using expo-secure-store with biometric access flags (kSecAccessControlBiometryAny). 3-Tier Socratic Hint Ladder: 1. Nudge: Why is AsyncStorage unsafe for auth tokens? 2. Visual Memory: AsyncStorage writes unencrypted plaintext JSON directly to an SQLite file on the device filesystem! Anyone with USB adb access can read it in 2 seconds. 3. Surgical Line Fix: Use SecureStore / Keychain which encrypts data with AES-256 keys managed by the phone's dedicated hardware cryptographic chip. Situational Production Puzzle (FAANG / Staff Screen): Scenario: A security firm performs a penetration test on your mobile app and extracts the user's banking session token from an unencrypted SQLite file in /data/data/com.app. What security control failed? Correct Answer: Option 2 &mdash; The app used standard AsyncStorage instead of the platform Hardware Keychain / Android KeyStore, violating financial compliance standards. Debrief: Financial mobile applications must store credentials and tokens in the platform hardware key vault (iOS Keychain with kSecAttrAccessibleAfterFirstUnlock / Android KeyStore), preventing extraction even from rooted devices.
