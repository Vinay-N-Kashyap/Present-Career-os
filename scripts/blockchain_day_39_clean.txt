Analyze the architecture: 1) Source Contract encodes arbitrary payload bytes; 2) Router / Endpoint emits message with unique messageId and source nonce; 3) Decentralized Oracle Network / Ultra-Light Node verifies and relays message; 4) Destination Contract executes `ccipReceive` or `lzReceive`. Solve the critical security challenge of cross-chain execution: Cross-Chain Replay Attacks (preventing a message executed on Polygon from being replayed on Avalanche or Arbitrum) and gas limit exhaustion on destination. A user submits a borrow request. The message arrives on Optimism, but the user's callback function reverts due to a temporary slippage error. The user's collateral is locked on Arbitrum, but they received no funds on Optimism. How does modern cross-chain messaging recover from failed destination executions?" Correct: Option B) Stored Message Fallback & Retryable Execution: Modern protocols (CCIP / LayerZero) catch execution reverts in the endpoint! The failed message hash and payload are stored in an on-chain mapping ('failedMessages[messageId] = keccak256(payload)'). Once market conditions normalize or the user increases slippage, anyone can call 'retryPayload(messageId, payload)' to re-execute the message without re-submitting the cross-chain transaction! • Debrief: In distributed cross-chain computing, destination transaction failures are inevitable. Protocols must never let failed messages drop into a black hole. Modern standards like LayerZero and CCIP store the failed payload hash on the destination chain, allowing users or automated keepers to retry the execution with updated parameters or higher gas.
