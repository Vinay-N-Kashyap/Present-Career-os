Concept Invariant &amp; Guardrail Push notification tokens can expire or change when an app is restored from backup or reinstalled. Clients must sync their active token to the backend upon every launch. Failure Mode: Sending sensitive personal data (account balances, passwords) in plain notification payloads, exposing data on the device lockscreen. Visual Memory: iOS APNs requires an Apple Developer Push Notification certificate/key and an active APNs token, while Android uses Google Play Services FCM tokens! 3. Surgical Line Fix: Ensure the backend maps both APNs device tokens and FCM registration tokens correctly. Situational Production Puzzle (FAANG / Staff Screen): Scenario: An enterprise backend sends 1,000,000 push notifications. 50,000 fail with 'BadDeviceToken'. What is the client-side cause? Correct Answer: Option 2 &mdash; The user uninstalled and reinstalled the app or updated iOS, invalidating the old APNs token. The client must register the new token on launch. Debrief: Device tokens are ephemeral identifiers. When apps are reinstalled or devices restored, APNs issues a fresh token. The client must report token refresh events to the backend immediately.
